# Workflow Writing

本文件是**写作流程的唯一权威**。每阶段只描述"目标 / 输入 / 产出 / 注意事项"四件事。

边界规则在 `CLAUDE.md`，角色与停顿决策在 `agent/writing-agent.md`，启动模板在 `agent/writing-start-prompt.md`。

---

## 阶段总览

```
0. 风格资产准备 ──(仅在指定风格时)
1. 碎片整理
2. 方向提炼
3. 大纲生成
4. 初稿生成
5. 风格应用 ──(仅在指定风格时)
6. 改稿与收束
7. 事实回顾
```

跳步规则：

- 没有风格需求 → 跳过 0 和 5。
- 改稿任务（revision） → 直接从已有草稿进入 6，然后 7。
- 蒸馏任务（distillation） → 不走本流程，参见 `.claude/skills/huashu-nuwa/SKILL.md`。

---

## 阶段 0：风格资产准备

**目标**：确认本次任务是否需要风格资产，以及这些资产是否已经存在。

**输入**：
- 用户指定的作者、学者、评论家或写作气质
- `.claude/styles/` 下已有的轻量风格卡
- `.claude/personas/` 下已有的完整人物视角

**产出**（仅本阶段判断，不产出文件）：
- 使用已有风格卡，或
- 使用已有 persona 辅助理解，或
- 启动女娲蒸馏新增风格资产（转入蒸馏流程），或
- 不调用风格，回到默认中文写作

**注意事项**：
- 已有风格卡足够时，不要重新蒸馏。
- 缺少对应风格卡时，不要临场伪造"像某某"的写法。

---

## 阶段 1：碎片整理

**目标**：从原始碎片中识别可展开主题、中心问题、情绪张力、关键句子、需要补充的空缺。

**输入**：
- `inputs/fragments/` 下的碎片
- 用户当前对话中补充的碎片
- 同主题旧稿（如有）

**产出**：
- 碎片简要归纳
- 2–3 个最有成文潜力的方向
- 每个方向对应的核心问题或判断
- 风险点清单（事实不足 / 情绪过强但结构不足 / 只是观点缺乏材料）

**注意事项**：
- 不要急于写正文。
- 不要把每条碎片平均对待，优先识别真正有张力的部分。
- 碎片若只是情绪宣泄，先寻找其背后的问题意识。
- 碎片若已包含强判断，先检查其是否值得成立，而不是直接放大。

---

## 阶段 2：方向提炼

**目标**：把零散碎片收束为少数几个可成文方向，判断哪一条最值得展开。

**输入**：
- 阶段 1 的归纳结果
- 用户的补充偏好（如有）

**产出**：
- 2–3 个候选方向，每个方向说明：
  - 写什么
  - 为什么值得写
  - 可能写成什么类型
- 默认推荐方向及理由
- 未被选择方向的放弃理由

**注意事项**：
- 候选方向之间应有明显差异，不要只是同一方向的轻微改写。
- 默认推荐必须说明依据。
- 用户未要求逐步确认时，可直接进入阶段 3，但要告知选择依据。
- 方向之间差异巨大且后果明显不同时，停下来向用户说明。

---

## 阶段 3：大纲生成

**目标**：将选定方向变成结构化论述路径，使文章在写作前就具备清晰骨架。

**输入**：
- 已选方向
- 原始碎片中的关键句子
- 风格要求（如已明确）

**产出**：
- 暂定标题
- 开头要解决的问题
- 主体段落的推进顺序
- 每一部分承担的功能
- 结尾的收束方式

**注意事项**：
- 大纲应体现"为什么下一段接着这一段"，而不是标题列表。
- 必须体现中心问题，不是材料堆积顺序。
- 应有推进关系，不是并列观点拼盘。
- 若风格调用会显著影响结构，在本阶段提前考虑，不要到正文阶段硬套。

---

## 阶段 4：初稿生成

**目标**：根据大纲生成结构完整、论述连贯、可读性成立的初稿。

**输入**：
- 已确认的大纲
- 原始碎片中的关键内容
- 风格与事实约束

**产出**：
- 标题
- 开头
- 主体段落
- 结尾

正文应能独立阅读，不只是扩写笔记。

**注意事项**：
- 初稿优先保证结构成立，第一版不必句句漂亮。
- 不要让风格先于论述。
- 事实不足时不要写得过满。
- 只能推测的地方在初稿阶段就保留审慎表达，不留隐患到事实回顾。

---

## 阶段 5：风格应用

**目标**：在不破坏文章成立性的前提下，对初稿应用指定风格。

**输入**：
- 初稿
- `.claude/skills/style-application/SKILL.md`
- 对应的 `.claude/styles/{name}/style-card*.md`

**产出**：
- 风格靠近后的文本
- 说明：本次调用了哪张风格卡 / 主要调整了哪些层面 / 哪些地方没有强化风格以保留清晰度

**注意事项**：
- 风格应优先作用于问题意识、推进方式、句法节奏、收束方式，而不是表面词藻。
- 风格卡信息不足时保守使用。
- 任务本身不适合强风格化时降低模仿强度。
- 调用后若文章只剩腔调没有论述 → 回退到初稿，重新评估风格调用必要性。

---

## 阶段 6：改稿与收束

**目标**：对当前文本进行整体修正，使文章从"能看"进入"能交付"。

**输入**：
- 初稿或风格化版本
- 用户反馈（如有）

**产出**：
- 一版更稳定的改稿（`draft-v2.md`），至少解决：
  - 结构松散
  - 逻辑跳跃
  - 语义重复
  - 语气失衡
  - 结尾无力
  - 风格压倒内容

**注意事项**：

改稿优先级（从上到下）：

1. 先修结构
2. 再修逻辑
3. 再修重复
4. 最后才是字词润色

不要一边结构失稳，一边花大量时间打磨句子。

---

## 阶段 7：事实回顾

**目标**：对涉及事实的内容做统一回顾，避免把不确定信息包装成定论。

**输入**：
- 当前草稿
- 已知来源
- 同任务目录中已有的 `fact-check.md`（如存在）
- `agent/fact-check-template.md`

**产出**：
- `runs/{experimental|formal}/{主题}/fact-check.md`，至少包括：
  - 需要核验的事实项
  - 已确认的事实项
  - 已主动保守处理的部分
  - 仍待补证据的部分
  - 当前版本是否适合进入正式版

**注意事项**：
- 区分事实陈述、分析、推断、印象。
- 不要因为正文写得顺就忽略核验。
- 优先检查：现实人物、真实案件、争议事件、引文、年份、作品名。
- 证据不足但又不宜删除的部分，降调表达并在 `fact-check.md` 中说明。
- 核验未完成时，不得把表述包装成已确定结论（见 `CLAUDE.md` 硬规则 7）。
